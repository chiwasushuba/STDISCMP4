## Behavior established

- Actual gRPC transport accepts valid signed JWTs and rejects missing/expired/wrong-issuer/wrong-audience tokens and unauthorized roles.
- A valid first grade row does not persist when a later row invalidates the upload.
- Two students competing for one seat produce one successful enrollment.
- Repeating enrollment does not consume another seat or duplicate the student/course record.
- Browser writes require CSRF tokens and student/faculty workflows enforce their backend permissions.
- A grade outage leaves course features usable, and a course outage leaves grade history usable.
- Existing authenticated sessions continue during a short identity outage, fresh login fails clearly, and fresh login succeeds after recovery.
- A grade-database outage affects grade features while the catalog remains usable.

## Limits

The tests ran on one Docker host. They establish process/database failure isolation, not machine-failure isolation across actual VMs. The networked deployment configuration is prepared and syntax-checked; it has not been deployed to external machines.

The web node, orchestrator, and each database have one instance. Database replication and automatic failover are not implemented. Database persistence and Hikari connection pooling are implemented. Grade rosters are synthetic registrar fixtures and are not automatically synchronized with current enrollments.

Automated accessibility checks and viewport emulation do not establish complete WCAG conformance, physical-device usability, or the owner's design acceptance. A manual screen-reader audit and formal load testing were not performed. HTTPS/gRPC TLS is not configured for the private local demonstration stack.

The source/build deliverables and demo scenarios are ready. The instructor's final test cases have not been provided; the final narrated/recorded submission and presentation deck remain to be prepared for that submission.

## Implementation findings

Standalone gRPC Spring Boot processes need an explicit lifecycle keeper when only daemon threads remain; these applications use `spring.main.keep-alive=true`. On Windows, the Oracle `javapath` launcher can create another JVM process, so the local launcher resolves `java.home` and tracks the real executable. These findings are recorded for this project; no global environment rules were changed.
